# Project Rules & Architecture Standards (Enterprise RAG)

## 1. LM Studio CLI Context & VRAM Management
- **Правило**: При загрузке моделей через LM Studio CLI (`lms load`) ВСЕГДА явно указывать контекстное окно `-c 8192` и флаг `--gpu max -y`.
- **Обоснование**: Модели с расширенным контекстом (напр. `qwen2.5-14b-instruct-1m`) по умолчанию пытаются зарезервировать KV-кэш на 1 000 000 токенов (требуется ~100 ГБ RAM/VRAM), что вызывает отказ `insufficient system resources`. С флагом `-c 8192` модель занимает ~8.5 ГБ VRAM и работает стабильно.
- **Жизненный цикл**: Модели выгружаются из GPU при закрытии RAG Studio через `lms unload --all`.

---

## 2. Динамическое переключение мульти-бэкендов (Ollama / LM Studio / Docker)
- **Изоляция в Streamlit**: В GUI-скриптах (`rag_gui.py`) всегда использовать `importlib.reload(server_manager)` при запуске страницы, а также функции-обертки с проверкой `hasattr()`, чтобы исключить `AttributeError` из-за устаревшего кэша в `sys.modules`.
- **Динамический AppConfig**: `RAGPipeline` при инициализации без явного `config` должен заново вызывать `dotenv.load_dotenv(override=True)` и создавать свежий `AppConfig()`, чтобы изменения в `.env` применялись немедленно без перезапуска процесса.

---

## 3. Автоматическая очистка портов перед стартом интерфейса
- Перед запуском нового процесса Streamlit в загрузчиках (`run_app.py`) обязательно сканировать целевой порт (`8501`) через `netstat -ano` и завершать любые оставшиеся зомби-процессы Python через `taskkill /F /PID`.

---

## 4. Проверка окружения Docker на Windows (WSL2)
- Перед вызовом `docker` или `docker compose` в пакетных скриптах и менеджерах бэкендов проверять доступность подсистемы WSL2 (`wsl -l -q`).
- Если WSL2 не установлена, сразу выводить рекомендацию `wsl --install` вместо долгого зависания на пайпе `docker_engine`.

---

## 5. Стандарты кодировки консоли Windows (cp1251 vs UTF-8)
- В любых Python-скриптах на первой строке выполнять `sys.stdout.reconfigure(encoding="utf-8")`.
- В консольных логах батч-файлов использовать маркеры совместимости `[OK]`, `[!]`, `[X]` во избежание `UnicodeEncodeError: 'charmap' codec can't encode character` в русской локали `cp1251`.

---

## 6. Таймауты холодного старта для локальных моделей 14B
- Таймауты HTTP-запросов к локальным эндпоинтам генерации и тестам бэкендов должны составлять не менее 20–30 секунд, так как начальная загрузка весов модели 14B с диска в память занимает от 8 до 15 секунд.

---

## 7. Разделение ресурсов: Эмбеддинги на CPU, Генерация на GPU
- **Правило**: Эмбеддинг-модели (напр. `nomic-embed-text-v1.5` / `text-embedding-nomic-embed-text-v1.5`) ВСЕГДА запускаются на процессоре (CPU / RAM):
  - При локальном расчете через `SentenceTransformer` / `torch`: `device="cpu"` (`EMBEDDING_DEVICE=cpu`).
  - При загрузке через LM Studio CLI (`lms load`): с флагом `--gpu off -y`.
- **Обоснование**: Эмбеддинг-модель весит менее 600 МБ и эффективно работает на CPU (десятки миллисекунд на чанк). Освобождение GPU от модели эмбеддингов гарантирует доступность 100% видеопамяти (VRAM) для 14B LLM модели генерации (Qwen2.5-14B) и исключает риск OOM (Out Of Memory) при одновременной работе стека.
